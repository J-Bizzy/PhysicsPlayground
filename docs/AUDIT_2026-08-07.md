## The one-paragraph verdict

The physics is the best in its category and the control vocabulary is better
than the platform's own. Two things are holding the app back, and neither is a
simulation problem. **First, the front door is broken**: since the focus panel
was deleted on 2026-08-04, the only way into a lab from the immersive gallery
is a sustained ~1.0–1.25 m pinch-drag onto a 0.105 m plate. The rule the project
wrote for itself — *nothing may be the only path to a capability* — is violated
at the app's entrance. **Second, the app's authored teaching is dark**: twenty
experiments with hand-written instructions, five premade circuits, five
Lagrange paragraphs, four pendulum explanations and six module promise lines are
all compiled into the binary with **zero readers**. The clutter the owner feels
is the visible symptom of the same structural gap: the design system has seven
control *shapes* and no *container*, so everything a module owns has to stand
in the room at full brightness at all times.

# P0 — fix first, they multiply across every module

### P0-1 · Every Bloom grip builds its leader rod from an undefined quaternion
**VERIFIED** · `Packages/RenderKit/Sources/RenderKit/Callout.swift:207`, caller
`PhysicsPlayground/DesignSystem/Bloom.swift:226`

```swift
// Callout.swift:207 — generateCylinder runs along +Y; aim it down the offset.
rod.orientation = simd_quatf(from: [0, 1, 0], to: offset / length)
```
```swift
// Bloom.swift:226
let callout = Callout(color: UIColor(white: 0.97, alpha: 1),
                      textSize: 0.019, offset: SIMD3(0, -0.046, 0))
```

`offset / length` is exactly `[0, -1, 0]` — antiparallel to `[0, 1, 0]`, where
`simd_quatf(from:to:)` is undefined. The project already solved this in the same
package and never reused the fix:

```swift
// VectorFieldArrows.swift:107 — the guard that exists and is not shared
if simd_dot(up, direction) < -0.9999 { return simd_quatf(angle: .pi, axis: [1, 0, 0]) }
```

Every per-object control ring in all six labs — a charge's magnitude, a cable's
length, a planet's mass — builds its value leader this way. Either a NaN
transform propagates into the leader subtree or the rod lands at an arbitrary
orientation.

**Fix:** promote `rotationFromYAxis(to:)` to a free `RenderKit.rotation(from:to:)`
with the near-antiparallel guard, and use it at all 13 `simd_quatf(from:to:)`
sites. Two of the others are reachable in ordinary use:
`FrozenVectors.swift:159` (a frozen gravity arrow points exactly `[0,-1,0]`) and
the four `from: [0,0,1]` yaw-facings in `Bloom:289`, `SpatialActionBank:193`,
`SpatialLayerBank:93`, `SpatialPicker:155` (a user standing directly behind an
instrument flips its plates upside down). The yaw cases should not use
`from:to:` at all — `simd_quatf(angle: atan2(flat.x, flat.z), axis: [0,1,0])` is
exact and degenerate-free.

### P0-2 · `SoundPalette.warmUp()` synthesises ~40 s of audio on the main thread at first launch
**VERIFIED** · `PhysicsPlayground/DesignSystem/SoundPalette.swift:33` and `:48-75`

`SoundPalette` is declared `@MainActor` (line 33), so the unstructured `Task {}`
in `warmUp()` **inherits the main actor**, and `writeIfNeeded` /
`writeAmbientIfNeeded` are synchronous — they run there, before the first
`await`.

```swift
static func warmUp() {
    guard !warmed else { return }
    warmed = true
    Task {                                                       // inherits @MainActor
        for sound in Sound.allCases {
            guard let url = try? writeIfNeeded(sound) else { continue }   // synth on main
            ...
        }
        if let url = try? writeAmbientIfNeeded() {                        // 36 s pad, on main
```

`synthesizeAmbient()` renders 36 s × 44.1 kHz, each sample summing 9 detuned
voice pairs — roughly 30 M transcendental evaluations — then `wavData` builds a
3.2 MB `Data` two bytes at a time. Called from `HubView.swift:72` and
`MainWindowView.swift:25`, i.e. during the first render of the home screen.

**Failure:** first launch (and any launch after visionOS purges the caches
directory) stalls the main thread for seconds. Invisible on a warm simulator
because the WAVs are already on disk.

**Fix:** `await Task.detached(priority: .utility) { ... }.value` around the
synthesis — the sample math is pure `[Float]` arithmetic and already `Sendable`
— and `reserveCapacity` on the `Data`.

# P1 — the front door

### P1-1 · There is no reachable way into a lab from the immersive gallery
**VERIFIED** · `Hub/HubSpaceView.swift:159-168`, `:733-741`; `Hub/HubView.swift:24`

A tap on an exhibit does this and only this:

```swift
guard scene.moduleID(for: value.entity) != nil else { return }
scene.hintPodium()          // flashes a plate 1.35 m away
```

Entry requires a sustained pinch-drag of ~1.0 m (nearest exhibit) to ~1.25 m
(outer) onto a 0.105 m pad, released inside a 0.34 m snap radius, then a pinch
on the Load plaque. `HubSpaceView.swift:15-20` still documents the focus panel's
Load button as *"the one that always works — gaze plus a pinch, nothing to aim
or carry… so neither is load-bearing alone."* The panel was deleted 2026-08-04.
DECISIONS.md 2026-07-29 states the pair "neither may be deleted without the
other changing."

This is the app's most likely one-star review: *"beautiful, but I couldn't
figure out how to start."*

### P1-2 · The main window is empty for the entire time the gallery is open
**VERIFIED** · `Hub/HubView.swift:24` — `if !appModel.isImmersiveSpaceOpen {`

Everything — the wordmark, the domain catalog, `AppProgressLine` (the app's only
view of experiment progress, streak and next step) — lives inside that branch.
`HubView.task` auto-opens the space at t ≈ 0.5 s, so within a second of launch
the window collapses to a blank 560×720 `.plain` frame that stays blank. The
"flat catalog is the accessibility path" guarantee is unmet in normal use, and
it is also the safety net that would cover P1-1.

### P1-3 · `isImmersiveSpaceOpen` is written by a `Group`, so it fans out to every child
**VERIFIED** · `Shell/PlaygroundSpaceView.swift:74-75`

```swift
}
.onAppear { appModel.isImmersiveSpaceOpen = true }
.onDisappear { appModel.isImmersiveSpaceOpen = false }
```

`Group` applies modifiers per child, and this `Group` has 1–2 children depending
on state (`StudioEnvironmentView`/`RoomDimmerView` plus the module `ZStack` or
`HubSpaceView`). Entering a dimmed module (Gravity Lab 0.85, Electric Fields and
Magnetism 0.35) removes one child and adds two; SwiftUI does not guarantee the
ordering. When the removal lands last, the flag reads `false` with the space
open — `ModuleHostView:188` offers "Show in room" for a lab already in the room,
and pressing it raises "Couldn't open the room."

**Fix:** move the pair onto a stable leaf (`.background(Color.clear.onAppear…)`)
or wrap the `Group` in a `ZStack`.

### P1-4 · Room dimming has zero paths — `cycleDimming()` and `setDimming()` are dead
**VERIFIED** · `Shell/AppModel.swift:104`, `:109` — the only caller of
`setDimming` is `cycleDimming`, and `cycleDimming` has no callers anywhere.

```swift
/// A manual change sticks for as long as the user stays in the module…
var roomDimming: Double = 0
func setDimming(_ level: Double) { ... }
/// Steps the shell through off → half → full, for the nav bead.
func cycleDimming() { ... }
```

The bead's four petals are pause, capture, settings, reset (`Palette.swift:155-160`).
Entering Gravity Lab darkens the user's real room by 85% with no control in the
window, none in the room, and none in Settings. That reads as a bug, and it is
the strongest form of the rule violation — *zero* paths, not one.

### P1-5 · A cancelled `retain()` leaks the ARKit session for the process lifetime
**UNVERIFIED (interleaving)** · `Shell/RoomModel.swift:188-289`, `:483-487`

`.task { await appModel.room.retain() }` cancels on disappear, but `retain()`
never checks `Task.isCancelled` and `release()` is guarded on `isRunning`:

```swift
func release() {
    clients = max(0, clients - 1)
    guard clients == 0, isRunning else { return }   // isRunning still false mid-start
```

Leave a lab inside the authorization window — trivial on first launch, where the
permission sheet is up for seconds — and `release` no-ops, then `retain`
completes and spawns three consumer tasks with `clients == 0`. Plane detection,
hand tracking and scene reconstruction run forever with the sensing indicator
lit and nobody reading them. `HubSpaceView:~150` has the identical pattern.

### P1-6 · A deliberate drag ends by throwing its own result away — twice
**VERIFIED** · `Shell/LabPlacement.swift:130` and `Hub/HubSpaceView.swift:217`

```swift
travelled = max(travelled, simd_distance(next, appModel.labPlacement.offset))
appModel.labPlacement.move(to: next)     // offset := next, so next frame measures ONE FRAME
```
```swift
barTravelled = max(barTravelled, simd_distance(next, placement.offset))
placement.move(to: next)
```

Both compare against a reference the previous line already overwrote, so the
quantity tested against the 0.012 m tap threshold is **one frame's hand
displacement**. Only a drag faster than ~1.08 m/s survives. Move the lab 60 cm
at a normal 0.3 m/s and `onEnded` takes the tap branch and calls `recentre()` —
the apparatus (or the whole gallery) snaps home and the drag is discarded. Both
are headline verbs of their objects and both are untested.

**Fix:** capture the start offset when the drag is created and measure against
that, or accumulate `+=` the per-frame delta instead of `max`.

### P1-7 · The permission prompt fires on the gallery with no context
**VERIFIED** · `Hub/HubSpaceView.swift:140` → `Shell/RoomModel.swift:200`

`room.retain()` starts the `ARKitSession` about one second after launch, before
any lab. The sentence explaining why ("visionOS will ask to use your room so the
lab can stand in it") lives in each module's `firstRunHint`, rendered in the
module *window*, which the user has not reached. A decline produces a warning
triangle in a title bar they may never look at.

### P1-8 · The only onboarding in the app renders in a window that may be behind the user
**VERIFIED** · `Shell/ModuleHostView.swift:239-268` is the sole render site for
`firstRunHint` (grep confirms). There is no in-room hint in any lab.

### P1-9 · There is no in-app way to close the immersive space
**VERIFIED** · `dismissImmersiveSpace` appears **0 times** in the app target.
A user who wants passthrough back mid-session must find the Digital Crown.

# P1 — spatial input correctness (the collider rule)

`DESIGN_SYSTEM.md:53` calls this absolute: *"A collider must never be larger
than the thing it represents… an app-wide input outage was traced to one
region-sized sphere."* It is violated in every module, and
`Grabbable.configureTouchTarget` only makes spheres, which is what forces it.

### P1-10 · Capacitor plates carry a 52 cm collision sphere
**VERIFIED** · `Modules/Electromagnetism/FieldRenderer.swift:357`

```swift
Grabbable.configureTouchTarget(plate, collisionRadius: 0.26)   // plate is 0.5 × 0.5 × 0.012
```

`plateSeparation` clamps to `0.15...1.0` and defaults to 0.44, so the two
spheres overlap through the whole capacitor interior; at the minimum gap plate
0's sphere extends 18 cm past plate 1. Every charge, the probe and the test
particle inside the field volume become unpinchable. `FieldSpaceView.resolveCharge`
mitigates this for *drags* only — the **tap** chain has no fallback, so a charge
inside the capacitor cannot be deleted or have its strength changed.

### P1-11 · Gravity Lab's clock bank has six discs laid out for four
**VERIFIED** · `Modules/GravityLab/GravityLabModel.swift:82` and
`GravityLabSpaceView.swift:119-120`

```swift
nonisolated static let timeScales: [Double] = [-20, -1, 1, 5, 20, 100]   // SIX
...
layout: FanLayout(span: 50 * .pi / 180, reach: 0.30, verticalScale: 0.25, ...)
```

The comment above the layout reasons explicitly about *"four discs at ±75° and
±25°"*. At six, adjacent end-pair centres are 0.0494 m apart; the disc is 0.052 m
across and its collider (`SpatialPicker.swift:255`) is **0.068 m**. The discs
visibly overlap and the colliders overlap by 27%. Aim at `1×`, hit `−1×`, and
the solar system runs backwards.

### P1-12 · The rest of the collider inventory
**VERIFIED** · sizes read at each site.

| Site | Visible | Collider | Consequence |
|---|---|---|---|
| `PendulumsRenderer:525` bob | r = 0.035 | 0.075 | cradle bobs are 0.07 m apart — every ball's sphere swallows both neighbours |
| `PendulumsRenderer:513` pivot | r = 0.014 | 0.05 | collars 0.07 m apart, same problem |
| `MagnetismRenderer:436` magnet | 0.16 × 0.05 bar | `half × 1.6` = 0.128 | two magnets at `contactDistance` 0.147 m shield each other |
| `CircuitsRenderer:825` terminal | r = 0.013 | 0.042 | reaches past the end grip at 0.115; on a short wire the two terminal colliders interpenetrate |
| `CircuitsRenderer:1185` wire | jacket 0.0062 | capsule 0.016 | — |
| `HubSpaceView:958` exhibit | half-extent 0.12 | 0.19 | puck pitch is 0.36 — adjacent exhibits interpenetrate by 2 cm |
| `GravityLabRenderer:271` body | `displayRadius` | `× 1.5` | an apsis bead drawn in the 1.0–1.5 r annulus is visible, hover-lit and unpinchable |
| `KinematicsRenderer:216,164,188,280` | ball/launcher/bead/hoop | 1.6–2.5× | — |

**Fix:** add `Grabbable.configureTouchTarget(_:box:)` and
`configureTouchTarget(_:matchingVisualBoundsOf:padding:)` (`Well.makeSource:175`
already demonstrates the second), bring every site to ≤ 1.15×, and add **one
criterion test** that walks every `CollisionComponent` in a built scene and
asserts each shape's extents ≤ its entity's `visualBounds` extents × a stated
margin. That single test catches P1-10, P1-11 and the whole table.

# P1 — gesture and lifecycle defects

### P1-13 · `PinchLedger.clear()` has no callers; one dropped event kills two-hand zoom for the session
**VERIFIED** · `RenderKit/SpatialScale.swift:137-152`

`owners` is pruned only by an event naming the id. Drop a hand out of the
tracking volume mid-pinch and that owner is permanent — `allowsScale` is false
forever and two-hand scale/turn silently stops working for the rest of the
module session.

### P1-14 · A suppressed two-hand gesture *commits* its partial scale
**VERIFIED** · `RenderKit/SpatialScale.swift:262-268` and `:275-277`

```swift
guard ledger.allowsScale else {
    rig.endGesture()      // endGesture() is `scale = liveScale` — the COMMIT, not a cancel
    return
}
```

Grab two different magnets; `MagnifyGesture` fires before the ledger resolves
both owners, so a partial swell lands and is then committed. The bench is left
permanently scaled — exactly the failure the same-object rule was written to
prevent. **Fix:** add `cancelGesture()` restoring the gesture-start values.

### P1-15 · `Bloom.configure()` clears the armed petal but not the in-flight grip drag
**VERIFIED** · `DesignSystem/Bloom.swift:187-231` vs `:490-518`

The header reasons carefully about the armed petal not surviving a rebuild and
misses `gripDrag`, which holds `(startHand, startValue)` captured against the
*old* grip. A selection change during a grip drag writes the old start value
into the new target's range. **Fix:** `gripDrag = nil` beside `armedPetal = nil`.

### P1-16 · `GeometryPipeline` cannot be cancelled and applies results after teardown
**VERIFIED** · `RenderKit/GeometryPipeline.swift:31-45`

The `Task` is never stored and neither loop checks `Task.isCancelled`. Leave
Electric Fields mid-trace and the detached compute runs to completion, then
uploads a `MeshResource` and enables an entity on a renderer whose scene is
being dismissed. Used by five renderers. **Fix:** store the task, expose
`cancel()`, check `isCancelled` after the `await`, call it from teardown.

### P1-17 · Nothing can clear `draggingID` except a normal `onEnded`
**VERIFIED** · `Hub/HubSpaceView.swift:682-690`; same shape in
`MagnetismSpaceView.swift:290-320` (`grabs`) and `KinematicsSpaceView`.

No timeout, no cancellation hook, no reset path. An interrupted drag strands the
exhibit (or magnet) wherever the hand left it and re-targets every subsequent
drag at the same object. The only exit is leaving the space.

### P1-18 · A tap on a pendulum bob stops it dead and wipes every trail in the room
**VERIFIED** · `PendulumsSpaceView.swift:299-441` (drag) vs `:459-499` (tap)

`DragGesture(minimumDistance: 0)` fires `onChanged` on a press, so a tap runs
`clearTrail()` + `beginGrab` + `release(handVelocity: ~zero)`. The file already
diagnoses this class for the *collar* and applies a moved/not-moved
discriminator; the bob kept a bare `TapGesture`. Same bug in
`KinematicsSpaceView.swift:296` — tap a flying ball and it stops in mid-air,
loses its strobe trail and its flight record, and hangs there permanently.
Gravity Lab has the fix (`minimumDistance: 0.012`); nobody else does.

# P1 — physics that is visibly wrong

### P1-19 · The double pendulum cannot draw its own trail, and every readout about it lies
**VERIFIED** · `PendulumsRenderer.swift:624`, `:386-397`, `:585`;
`PendulumsModel.swift:434-440`

`step` never writes `state` for `kind == .double` — only `doubleState`. So
`state.position` is a plumb bob at rest and `state.velocity` is identically zero
forever. Consequences, all at once:

- the trail guard `speed > 0.02` never passes, so the chaotic trace — the one
  image `DoublePendulum.swift`'s header says the rig exists for — is undrawable;
- the force/tension/net arrows draw a constant `mg` up and `mg` down anchored on
  a bob that is visibly accelerating hard, and the net arrow is hidden;
- `syncPeriodLabel` stamps `T = 2π√(L₁/g)` over a system with no period;
- `PendulumInfoCard` shows `θ 0°  v 0.00 m/s` permanently;
- the notebook writes `Speed 0.000 m/s`;
- `FrozenVectors` samples the same state, so pausing a double produces no freeze
  sculpt at all;
- grabbing the bob freezes it, refuses to follow the hand, shows a ghost that is
  a single degenerate point, and resumes exactly where it stopped.

### P1-20 · The ammeter has exactly two reachable outputs: `FUSE` and zero
**VERIFIED** · `Modules/Circuits/CircuitsModel.swift:1006`

The meter is never stamped into the network, so `amps` is the component's own
current and the only way past the `|amps| > 1e-9 → FUSE` branch is a value that
`autoRange` prints as `0.000 A`. Worse, the threshold sits **below**
`CircuitSolver.leakConductance`'s own floor, so an open switch still leaks
9e-9 A and the meter shouts *"the Bulb is live — break the loop first"* on a
loop the user just broke. `CircuitsModelTests` tests the refusal path and never
the success path, which is why it shipped.

### P1-21 · Electric Fields reports the electric force while the headline demo is magnetic
**VERIFIED** · `Modules/Electromagnetism/FieldModel.swift:740`, `:746`, `:197`

`stepProbe` uses the full Lorentz push `q(E + v×B)`; `probeReadout` computes
`F = |q||E|`. Switch **Uniform B** on with no charges and the card reads
`Force 0.00 N` while the probe visibly circles at `a = v²/r ≈ 0.35 m/s²`.
`potential` sums only the point charges and ignores the capacitor, so the card
can show a large `E` beside `0.00 V` — the one thing a potential cannot be. And
`cyclotronRadius` is quoted from the constant `launchSpeed = 0.35`, which the
probe leaves within a fraction of a second under Coulomb.

### P1-22 · Magnetism's magnets move through a field that is not the field being drawn
**VERIFIED** · `MagnetismModel.swift:241-243` vs `MagnetismRenderer.swift:503-514`

Dynamics use `MagneticField.netForce`/`vector` (point dipole); the loops are
traced with `barVector(length: 0.16)`. `MagneticField.swift:50-62` disqualifies
the point dipole itself — *"it is simply not the field of a bar magnet any
nearer than a few bar-lengths… the correct picture of the wrong object"* — and
`contactDistance = 0.147 m` puts the dynamics at r/L ≈ 0.92. The module's most
repeated interaction (two magnets snapping together) is computed in the regime
the code's own header rules out.

### P1-23 · Gravity Lab's orbit-ring occluders are passed in the wrong frame
**VERIFIED** · `GravityLabRenderer.swift:509-519`

`OrbitRing.place` computes the bead **relative to the focus**;
`isOccluded` compares it against **absolute** body centres. Masked only because
`reset()` puts the Sun at the origin. Press "Twin suns" (primary at ±0.2 AU) and
every occlusion test is offset — beads inside planets stay targetable, beads in
open space get hidden and stripped of `InputTargetComponent`.

### P1-24 · The predicted arc and the real ball bounce differently
**VERIFIED** · `PhysicsCore/Kinematics/ProjectileMotion.swift:169-177` vs
`KinematicsModel.swift:647-666`

`simulate` passes `radius: 0`, ignores `hit.t` (so the remainder of the frame is
never spent — the exact defect `RoomWalls.Hit.t`'s own doc says "deadened every
fast bounce"), and bounces the ball *centre* off `y = 0`. The live model does all
three correctly. With a basketball (r = 0.121 m) the white predicted arc corners
12 cm off the wall and 12 cm above every floor bounce, and each subsequent
segment compounds it. "Predicted arc, bounces included" is the module's central
claim.

### P1-25 · Bob collision impulses are applied off the constraint tangent, then reinterpreted as speed
**VERIFIED** · `PendulumsModel.swift:506-507` with `Oscillations.swift:79-96`

`normal` is the line of centres, not tangent to either constraint sphere.
`SphericalPendulum.step` then projects for *direction* but takes speed from the
work–energy theorem using the **unprojected** velocity, so the radial component
the collision injected becomes extra tangential speed. Two pendulums at
different heights gain energy on every contact. Masked in the cradle (normals
are nearly tangent), and the cradle is the only collision test.

### P1-26 · Collisions switch off for the entire bench if two pivots coincide
**VERIFIED** · `PendulumsModel.swift:473-478`

```swift
guard simd_length(axis) > 1e-6 else { return }   // aborts resolveBobCollisions for EVERYONE
```

`movable.first`/`.last` are array order, not spatial order. Pull two pendulums
from the well without moving either — both land at `defaultPivot` — and no bob
in the room collides with any other, including a cradle standing beside them.
The axis is only used for *sorting*; the guard should skip the sort, not the
resolution.

### P1-27 · `removeComponent` leaves `pendingTerminal` dangling → permanent zombie wires
**VERIFIED** · `CircuitsModel.swift:609` vs `:511`

Pinch a terminal (arms it), open the part's ring, tap Delete. `pendingTerminal`
still names the destroyed part; the next terminal tap appends a `Wire` whose
`from` component does not exist. It is invisible (`isEnabled = false`) and
therefore un-pinchable, permanently consumes one of the 36 budget slots, and is
written to `UserDefaults`. `connectTerminals` validates both ends;
`removeComponent` — the one the Bloom actually calls — clears neither.

### P1-28 · Six of eleven circuit parts teleport 16 cm the instant they are born
**VERIFIED** · `CircuitsPartsLayout.swift:106-107` vs `CircuitsModel.swift:41`, `:285`

The outer rack columns sit at x = ±0.86; `add(_:at:)` clamps to
`buildHalfExtents.x = 0.70`. Battery, Switch, Wire, Capacitor, Bulb and Motor
all jump inward at creation, defeating the well's stated purpose (*"born at the
fingertips, not at the source"*). `CircuitsPartsLayoutTests` checks reach,
angle, mirroring and pitch — never a slot against the clamp box.

### P1-29 · Magnetism's field-line job is ~10× heavier than its sibling and resubmits every drag frame
**VERIFIED** · `MagnetismRenderer.swift:479-537`, `MagneticFieldLineTracer.swift:224-269`

`maxSteps = 2400, stepSize = 0.008` against Electric Fields' `220 / 0.012`, then
an O(|a|·|b|) dedup sweep over ~300–600-point polylines for every accepted line,
both directions. `GeometryPipeline` coalesces but does not cancel, and
`syncFieldLines` resubmits on any change to `[BarMagnet]`. Drag a magnet and the
loops freeze at the state they had when the drag started.

### P1-32 · The entire spatial control vocabulary is unreachable to VoiceOver
**VERIFIED** · `grep -rn "systemActions\|AccessibilityEvents"` returns **zero

// SpatialTrackControl.swift:274 — a track replaces a `Slider`, and a slider is

|---|---|---|

| Pendulums | 6 | ✅ |

Three causes, none of which is "too many features":

1. **Flat banks that never fold.** `SpatialLayerBank`'s argument — a bank is a
   readout as well as a control, so it must not fold — holds at 4 plates and
   fails at 7. Nobody reads seven lamps as a state; they read a wall of switches.
2. **Category errors on the bank.** Gravity Lab's bank carries `velocity`,
   `acceleration`, `force` — three *per-body annotations* — beside `grid`,
   `sweep`, `particles`, `lagrange`, which are *system-wide overlays*. The three
   belong on the selected body's ring, which already exists. Pendulums does the
   same.
3. **Everything is at 100% brightness all the time.** The hub already knows
   better (focus recession; *"emphasis is opacity, light and sound — never
   geometry"*, DECISIONS 2026-07-30). The labs never adopted it.

**The structural cause:** the design system has seven control *shapes* and no
*container*. Every primitive is a peer with its own anchor, its own `update`
signature, its own collider and its own tap entry point. Symptoms in the code:

- five different per-frame signatures (`Well.update(dt:)`,
  `SpatialLayerBank.update(anchor:viewer:dt:)`,
  `SpatialActionBank.update(anchor:viewer:dt:resetNonce:)`,
  `Bloom.update(anchor:viewer:revealTarget:dt:)`,
  `SpatialTrackControl.refresh()`), so "nothing ticks itself" is a promise the
  caller can silently break — and does (`KinematicsSpaceView:427` vs `:434`);
- six hand-written ordered `if a.handleTap { return }; if b.handleTap …` chains,
  each with its own reasoning comment: priority expressed six times as control
  flow;
- `FieldInstrumentLayout.swift` (274 lines) exists solely because one module had
  to hand-derive clearances between instruments with no common parent. The other
  five have no clearance guarantee at all, and
  `SpatialActionBank.reach(forLabels:)` — the API meant to provide it — has zero
  production callers.

# Test-coverage gaps that let the above through

The project's stated pattern — *"build real entities, invoke `handleTap`,
because no automation can synthesise a pinch"* — is carried by four suites. The
code it does not reach is exactly where the P1s are.

1. **The hub's docking handlers have no test at all.** `beginExhibitDrag`,
   `dragExhibit`, `endExhibitDrag`, `moduleID(for:)`, `hintPodium` and
   `seatLoadButton` are all internal, `@MainActor`, and directly callable.
   P1-6, P1-17 and the podium-hint race are all in code this pattern would have
   covered for free. There is no `HubDockTests`.
2. **No collider criterion test.** One test walking every `CollisionComponent`
   in a built scene, asserting extents ≤ `visualBounds` × margin, catches P1-10,
   P1-11 and the whole P1-12 table at once.
3. **`FanLayoutTests` uses the wrong radius (0.052, the *visual* diameter, not
   the 0.068 collider) and stops at count 9**, testing only the default layout —
   never the two custom layouts the modules ship. That is why P1-11 landed.
4. **Four of six modules have no Time Capsule *replay* test** — only
   capture→mutate→restore→re-capture, which reads only the fields already in the
   snapshot and therefore cannot detect a missing one. The file's own header
   forbids exactly this weakening.
5. **`PanelControlCriterionTests` never scans the shell**, so `ModuleHostView`
   itself can grow a `Slider`.
6. **`MaterialCanonCriterionTests` and `AccentAuthorityTests` never scan
   `Hub/` or `DesignSystem/`.**
7. **No test covers the double pendulum's rendering path, the bob press-vs-drag
   discriminator, off-axis bob collisions, `setLength`'s floor interaction, the
   focus hysteresis, or the ammeter's success path.**

# What is already better than anything else on the platform

Worth stating plainly, because the plan below is all criticism and the base is
strong:

1. **It is a simulator, not a diorama.** Nodal analysis every frame, real
   Newtonian n-body, live field-line tracing. Nothing in the category is close
   on physical honesty.
2. **The control language is novel and more coherent than the platform's own.**
   Plates, rails, wells, rings — and `PanelControlCriterionTests` enforcing it.
3. **True 1:1 room scale.** Bouncing off *your* wall, catching a ball on your own
   tracked fingertips, walking into an orrery at 9×.
4. **The Time Capsule.** Pausing into a walkable frozen instant with the reel
   turning by arc ÷ radius is a better idea than anything shipped in this
   category — and it is currently off by default and unmentioned in the listing.
