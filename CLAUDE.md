# CLAUDE.md

**Physics Playground** — visionOS app. Room-scale physics labs, each fully volumetric and grabbable in the user's actual room. Portfolio project for college applications, so the physics must be genuinely correct: SI units, real constants, exact closed-form solutions where they exist, pure Swift with no physics libraries, tests written alongside the feature.

Deeper structure lives in `docs/ARCHITECTURE.md` — read it before adding a module or moving code between layers.

## Git safety

The parent directory (`Desktop/VisionPro`) holds sibling projects and a stray embedded repo (`cool/`). **Never `git add -A` or bare `git commit -m` from outside this project** — the index can carry pre-staged sibling files. Always commit with an explicit pathspec scoped to this project.

## Build & test

```bash
# Fast loop — pure physics, native on the Mac, no simulator:
cd Packages/PhysicsCore && swift test
cd Packages/PhysicsCore && swift test --filter MagneticFieldTests

# Full app build + app-level tests (needs the simulator):
xcodebuild test -project PhysicsPlayground.xcodeproj -scheme PhysicsPlayground \
  -destination 'platform=visionOS Simulator,name=Apple Vision Pro 4K'
```

Three suites, and the split is about what each CAN reach:
- `PhysicsCoreTests` — pure math, fast, no simulator.
- `PhysicsPlaygroundTests` — models, clamps, layout, and **tap handlers called directly**: build real entities, invoke `handleTap`, because no automation can synthesise a pinch. Four suites carry that pattern — `SpatialTapTests` (the layer bank and the picker), `SpatialActionBankTests`, `BloomPetalTests`, `MultimeterTests`. (Docs cited a `StationTapTests` here until 2026-08-02; no such file ever existed — the name is from the merged-worlds era, undone on 2026-07-30. The pattern outlived the name.)
- `PhysicsPlaygroundUITests` — real XCUITest taps on the **window** surfaces. Launch with `-uiTesting 1`, which gets the flat catalog on screen so XCUITest has something it can see; it cannot see anything in an immersive space. **What that argument DOES changed on 2026-08-22**: it used to suppress the window's automatic opening of the gallery, back when the window was the launch scene. The ImmersiveSpace is the launch scene now (`Info.plist`'s `UIApplicationPreferredDefaultSceneSessionRole`), and no launch argument can reach a static plist key — so `PlaygroundSpaceView.retreatForUITesting` turns round on the way IN and dismisses the space instead, letting the existing `onDisappear` hand the window back. It must not open the window itself: doing both produced two, with the catalog still up behind the module, which is precisely what `testTappingALabEntersIt`'s last assertion catches.

**Nothing automated can touch a RealityKit entity.** `simctl` has no tap verb and XCUITest has no entity API, so every spatial gesture — drag to the podium, pinch a magnet, two-hand zoom — is verified by hand against `docs/ON_DEVICE_TESTS.md`. A screenshot proves something rendered; it never proves it works.

The simulator can't be gaze-pinched, so debug launch args drive a module into a given state for CLI screenshots. Shell-wide: `-openModule <id>`, `-studioMode 1`, `-startPaused 1`, `-pauseAfter <seconds>`, `-resetHints 1` (all in `AppModel.init`); `-timeCapsule 1` (`AppSettings.swift` — the master switch; the two below do nothing without it), `-scrubBack <seconds>`, `-scrubStep <n>` (`TimeRail.swift`); `-paletteOpen 1` (`Palette.swift`); `-uiTesting 1` (retreats out of the space so XCUITest can see the flat catalog); `-settingsOpen 1`, `-notebookOpen 1`, `-notebookSeed 1`, `-seedCircuits 1`, `-seedMotor 1`, `-circuitVoltageHeights 1` (**`PlaygroundSpaceView.swift` since 2026-08-22** — they lived in `MainWindowView` until that window stopped being the launch scene, and they must be read BEFORE the `-uiTesting` retreat, since the settings UI test passes both); `-roomSensing denied|unsupported|failed` (`RoomModel.swift`); `-hubDock <module id>`, `-hubFocus <module id>`, `-hubIntro <seconds>` (freezes the home's arrival choreography at that instant — it is wall-clock and over in four seconds, so a photograph needs the clock pinned; `HubSpaceView.swift`). Per-module ones are listed below. **There is no single file holding them all — `AppModel.init` reads five of sixty — so `grep -rho 'forKey: "[a-zA-Z]*"' --include='*.swift' PhysicsPlayground | sort -u` is the only honest index.** (It said fifty-six until 2026-08-09, which is the argument for the grep rather than against it: a hand-kept count drifts by exactly the arguments somebody added without updating the sentence.)

The home's display type is no longer a setting: the machined plaque ships, and as of 2026-08-02 it is the only thing `HubTitleStyle` can draw. The specimen wall, the Settings picker, and the three losing voices are all gone, and so is the enum itself — a four-case taxonomy with one reachable case, a `shipping` constant, a `current` global and a `switch` in every method is a choice mechanism with nothing to choose. `HubTitleStyle` is a namespace now, not a type you pick from. The argument lives in DECISIONS.md and the git history. `-electronView 1` shrinks the bench into the copper (its switch is a plate on the in-room layers bank, which the simulator cannot press). Scenes read the bare `-viewScale`.

**Gravity Lab's orbit ring is its centrepiece and cannot be pinched from the CLI**: `-selectBody <name>` picks the planet whose ring is drawn, and `-apsisDrag near|far,<factor>` actually RESHAPES that orbit — `-apsisDrag far,2.2` pulls apoapsis out to 2.2× its radius. It has no panel at all: the display layers are a switch bank, G is a rail, and the star's mass is a bead on the star, so all three need `-openModule gravitylab` plus a hand or an argument. `-gravRing 1` opens a body's control ring; `-predict 1` arms the ghost. `-gravLagrange 1` lights the Lagrange layer AND parks a body at L4, which is the only way to photograph the capture paragraph — like `-apsisDrag`, it reaches a capability rather than a control, because the paragraph appears on a RELEASE near a point and the simulator can neither pinch nor let go.

**Electric Fields is fully spatial** — every control is an object in the room, so nothing in it can be reached from the CLI without an argument: `-emCap 1`, `-emLines 0`, `-emParticle plus|minus`, `-emVolts <V>`, `-emTesla <T>`, `-emProbeCharge <C>`, `-emRing charge|probe`, `-emDielectric <0..1>` (slides the capacitor's dielectric slab in by that fraction — the crowding it causes only exists at partial insertion, so the value matters, and it is read with `double(forKey:)` because the argument domain stores strings), `-emLaunch 1` (fires the deflection shot through the gap; pair with `-pauseAfter` to freeze the parabola mid-bend), plus the older `-emMagnetic`/`-emProbe`/`-emFree`. The capacitor is REAL finite plates since 2026-08-14 (`PlateField`, closed-form charged rectangles, charge calibrated to hold the set ΔV): the traced lines run the gap and genuinely fringe, the readout's E is the measured centre field honestly below V/d, and C, Q, U are measured, not the textbook formula. (The flux meter, its `-emGauss`/`-emRadius`/`-emTilt` args, the particle bank and electron mode were removed 2026-08-03.) The VALUE arguments matter as much as the on/off ones: a rail whose bead sits at its default in every screenshot proves nothing about the mapping behind it.

**THE ROOM'S BRIGHTNESS IS ONE NUMBER (2026-08-09).** Five modules open at `preferredDimming` 0.35 and Gravity Lab at 0.85 with a 16 m shell and `.progressive` immersion — one exception, argued in its own descriptor, because a pale Sun and specks of planet have no contrast against a lit wall. Before this, three modules opened at 0 and three at 0.35, so cutting between labs changed how bright the wearer's own living room was. `AtmosphereCriterionTests` allows exactly one departure from the house value and requires that any module dimming past 0.5 also move its shell out — heavy dimming at the default 3.4 m radius draws the shell *through* the apparatus.

**AND YOU HAVE TO BE ABLE TO REACH THE CONTROLS.** `InstrumentClearance.maximumReach` is 1.25 m and until 2026-08-09 it was checked in exactly one module: every other bank anchor was a `SIMD3` literal inside a render closure where nothing could measure it. Three surfaces were out of reach and all three are fixed: Gravity Lab's verb bank (1.36 m, now 1.13), Projectiles' instrument wall (was 1.67 m — the placement pass happened; the wall is now a single column at −0.90/−0.94, every anchor ≤ ~1.20 m), and Gravity Lab's clock tab (was 1.33 m, now stacked on the verb flank at ~1.17). Every module's bank anchor is a named `static` on its SpaceView so `InstrumentReachCriterionTests` can measure it, and the test's `knownUnreachable` list is EMPTY — nothing is exempt. (This paragraph recorded the wall and the clock tab as open failures until 2026-08-14, well after both fixes had landed and the test had gone green with no exemptions — the same drift the launch-args paragraph above documents, in the file that documents it.)

**THERE ARE NO MODULE PANELS (2026-08-01).** `makeControls` is deleted from `ModuleDescriptor` and the six `*ControlsPanel.swift` are gone. A module's window is a title bar, plus "Show in room" while the immersive space is closed — and, while it is closed, the first-run hint. **The teach lives ONLY in that window (2026-08-09).** It moved into the room on 2026-08-08 (`Shell/RoomTeach.swift`) because the apparatus renders in front of a window behind it and was crossing the sentence out; the fix worked and produced a paragraph standing in FRONT of the bench instead, covering the thing it described. The owner deleted it, along with Circuits' insight card. **A paragraph is the wrong shape for this room** — three cards of words have now been rejected in three days — so nothing in a lab explains itself in prose; the apparatus does. Every control and every readout stands on the apparatus and `PanelControlCriterionTests` fails the build if a panel comes back. (A companion test failed any experiment step that said "in this window"; it went with the experiments system on 2026-08-09 — see below.) So every module needs an argument to reach its controls from the CLI:
- **Pendulums** — `-penLayers 1` (lights all four of the bank's plates; the Foucault rig and its fifth plate were removed 2026-08-03), `-penRing 1` (the bob's ring, and the only way to see the floating readout card), `-penPivotRing 1` (the collar's ring: cable bead and trash). **`-penGravity <m/s²>` and `-penTime <×>` are different in kind from every other argument here:** the rest reach a control a hand could also reach, and these two reach a capability that was RETIRED on 2026-08-02 along with its rail. A wearer cannot change g or the clock in this module. Use them to photograph the bench somewhere other than Earth at 1×, not to stand in for a missing finger.
- **Magnetism** — `-magInertia 1` swaps the overdamped glide for magnets with real mass and rotational inertia (a needle overshoots and rings); the glide is still the default, and DECISIONS.md 2026-08-03 records why both ship. `-magLayers 0` darkens three of the bank's four plates (the compass grid and its plate were removed 2026-08-03; the scene opens with several lit, and there is no finger to flick them with); `earthFieldOn` is the fourth and the argument does not reach it. `-magRing 1`, `-magFrozen 1`.
- **Projectiles** — `-kinGravity <m/s²>` (also lights the matching world disc), `-kinWind <m/s>` (switches the air on, since the wind rail does not exist without it), `-kinBalls 1`, `-kinWalls 1` (`2` also fires a 12 m/s hand-speed ball at the seeded wall — the fast regime the 2026-08-06 bounce fixes exist for; the gentle welcome shot alone proves nothing about tunnelling).
- **Circuits** — `-electronView 1`, `-trueSpeed 1`, `-circRing 1`, `-circClear 1`, `-skyline 1` (the voltage skyline), `-circField 1` (the wire's own magnetic field), `-circPreset <name>` (loads one of the five authored circuits), `-circPresetsOpen 1` (unfolds the presets column behind its tab — the only CLI reach to that surface, since every plate on it `confirms` and the simulator cannot tap twice), `-circScroll <n>` (scrolls the parts rack), `-circAlign 1` (drops two parts within reach and fires the release, so the SNAPPED chain is what a still frame holds), `-circLead <componentIndex>,<end>` (a lead in flight from that terminal toward open air — the neutral copper state) and `-circSameNet 1` (the same lead pulled onto a terminal it is ALREADY joined to, held in its refusal). `-circUnplug <wireIndex>,<end>` lifts that end of that wire into the air and holds it there, with the circuit DARK, and `-circHighlight <componentIndex>,<end>` lights that terminal's whole net, and `-circSag <ratio>` forces the slack so a still frame can show the curve at a chosen depth (`-circSag 0` proves the straight fallback — and it is read as an `NSNumber`, not a `Double`, because `-circSag 0` is stored as an integer and a Double cast silently does nothing). **Those three run AFTER the bench-shaping arguments and that ordering is load-bearing:** they name a component index, a wire index, a terminal, and `-circPreset` starts with `clearBench` — run earlier they name parts a preset then deleted, which is exactly how `-circPreset series -circHighlight 0,1` first photographed no highlight at all with the suite green. These three exist because a lead in flight is a gesture state, and the simulator can only reach one by being handed it.

**WIRES HANG (2026-08-11).** A connection is drawn along a true catenary — `PhysicsCore/Circuits/Catenary.swift`, parameter solved by Newton on `2·sinh(aL/2)/a = S`, degrading to the chord for a near-vertical or slack-free span. Not a bezier: this module's claim is that its pictures are physics. **Slack is ZERO for a span within `leadReach`**, which is what stops sag undoing snap-align's tidiness — a snapped joint has no cable to hang, and most joints on a chained bench are snapped. A hanging cable is drawn from SEGMENTS sharing one unit-cylinder mesh, never a regenerated `TubeMesh`: the house rule is that the per-frame path touches only transforms, and a wire on a carried part moves every frame. **The segments carry no collider** — a segment encodes its length as a Y scale, and `ColliderCriterionTests` reads any collider under a world scale below 0.05 as a folded instrument it cannot honestly measure. The grab volume is three capsules on the unscaled parent, following the curve, rebuilt only when an end moves 2 mm. `conductingPathLength` sums ARC rather than chord, because an electron walks the cable and the true-speed readout is built on that number.

**TAP A LEAD AND ITS WHOLE NET LIGHTS (2026-08-11).** The one question a circuit builder asks constantly — *what is this connected to?* — had no answer in the room: a terminal wired through three hops looked exactly like a terminal wired to nothing. `highlightedNet` lights every terminal at that potential and every wire between them, in the module accent, over the top of the voltage ramp for as long as it is lit. It is **selection-driven, not hover**, and that is a limit rather than a preference: `HoverEffectComponent` is system-drawn with no callback and there is no hover event without `SpatialEventGesture`. Tapping empty space clears it, symmetric with the ring fold. It is an `Int?` and not a `Bool` deliberately — `ResetCoverageTests` reflects over `Bool`s and this is a selection, not a display layer — so `CircuitsNetHighlightTests` covers reset/clear/capsule by hand.

**A WIRE COMES OFF BY BEING PULLED OFF (2026-08-11).** `beginRewire` lifts one end of an existing wire into the same lead pull, drawn from the end that stayed — so moving a connection is one gesture instead of destroy-and-redraw. **The wire leaves `wires` the moment you lift it, and that is the teach, not an implementation detail:** the circuit goes dark in your hand, and a bulb going out as you lift a wire says what that wire was doing better than a label on it could. Three landings: another terminal rewires, the original terminal restores, open air deletes. A REFUSED rewire restores rather than deleting — losing a connection because you aimed at an illegal target is the harshest possible reading of a "no". The last three were undocumented everywhere until 2026-08-09. **`-circLegacyBench 1` is different in kind from all of them:** it writes a PRE-MIGRATION bench into `UserDefaults` from inside `CircuitsModel.init`, before the model reads it, because nothing else can stage a migration — the running app cannot mint a retired kind, and by the time any view has appeared the bench is already restored.

**WIRING IS ONE GESTURE: PULL A LEAD (2026-08-11).** There were three, on thresholds that disagreed — tap-tap (`tapTerminal`/`pendingTerminal`), drag-to-wire (a hardcoded 0.09 measured hand-to-terminal), and magnetic auto-connect on release (`snapDistance` 0.13). Two of them could fire from ONE EVENT: this view carries a single `DragGesture(minimumDistance: 0)` — it has to, because the rack pull must claim the first frame — so every tap also ran the drag, and a tap on a terminal armed the wiring through the tap gesture AND completed a different wire through the drag, in an order nothing defined. Tap-tap is deleted and `PressLatch` now gates the drag: a press promotes to a pull only past `tapTravel` (12 mm), so a zero-travel press cannot wire anything. **A tap selects; it never wires and never deletes** — tapping a wire used to destroy it outright, with no confirmation, on a bench that survives relaunch. The half-made wire lives in the MODEL as `LeadPull` (so `removeComponent` can cancel it — that is where the zombie-wire class died) and carries its `refusal` computed a frame BEFORE the release, so what you preview is what you get including the "no". **The refusal is a RECOIL, not a sentence:** the lead shortens back toward its source, goes red and thickens. Tap-tap survives for VoiceOver only, as `voiceOverWire`/`voiceWireSource` — named apart from `pendingTerminal` on purpose, and the pinch path never reads it. `CircuitsSpaceView.resolveGrab` is a pure static over entity names (following `FieldSpaceView.resolveCharge`) so the six-way priority order is testable without a headset, and it has **no distance fallback**: one part's two leads are 17 cm apart, so a fallback is how you wire the wrong end.

**ONE GRAB TARGET AT EACH END (2026-08-11).** Every part used to carry FOUR touchable balls: a copper terminal at ±0.085 and an orange end grip at ±0.115, each with a 0.026 collision radius — 3 cm apart with hit volumes that overlapped, so which one you grabbed was decided by hit order. That is the "2 different nodes at each end" the owner reported. The grips are deleted; the copper lead is the only thing at an end. The body's carry target was a 0.075 sphere that swallowed the inner third of both lead colliders, and is now a box measured from the BODY (not the holder, which collects a bulb's glow and a selection halo) with its x half-extent clamped just inside the lead's inner edge at 0.059. Aiming, which was the grip's job, is a consequence of connection now: `CircuitsModel.swing` swings a part hanging by ONE wired lead about that lead, and `alignment(for:)`/`release(id:)` snap a released part nose-to-tail onto a neighbour's lead — moving and rotating it about the landing joint, never moving the target, which is also what stops a cascade. `leadReach` (0.06) is the single distance that replaced `snapDistance` 0.13 and a hardcoded 0.09 that disagreed about the same fact by 44%.

**THE JUMPER IS NOT A PART ANY MORE (2026-08-11).** `ComponentKind.wire` is retired: a *connection* spans any distance now, so a jumper part had nothing left to do, and the bench stops having two different things called "wire". Retiring a `Codable`-by-rawValue enum case is the dangerous half — decoding straight into `[Component]` throws for the WHOLE array on one unrecognised kind, and both restore paths swallow that with `try?`, so the naive deletion silently empties every saved bench and all eight named slots on first launch and the app looks like it is working. The bench is read through `StoredComponent`/`StoredBench` (kind as a raw `String`) and `migrated(_:)`, which SPLICES a retired part rather than dropping it — its two ends were one electrical point, so everything joined through it stays joined. `CircuitsBenchMigrationTests` holds this, and its last test uses a kind that never existed rather than the one just retired, so it goes on meaning something after `.wire` is history.

**A destructive plate is screenshot ARMED, never fired.** `-emClear 1`, `-circClear 1` put the plate into its armed state (lit lamp, nameplate swapped to "Tap again") and hold it there past the four-second timer, because firing photographs an empty room — which looks the same as a room nobody filled. Gravity Lab's two verbs are `-gravBinary 1` and `-gravWorlds 1` (the ten-preset fan). **Pendulums has no verb plate at all** — "Resonance ×5" came off the wall on 2026-08-02, so three modules carry one, not four.

**The Time Capsule SHIPS OFF** (`AppSettings.timeCapsule`, Settings → Time Capsule; owner's call 2026-08-07). The default app is six labs where pause means the room holds still. The switch gates the RECORDING, not the reel — `TimeCapsuleSettings.isEnabled` is what every model's `recordCapsuleFrame` asks, so switched off nothing snapshots itself and the feature costs what it cost before it existed; switching it off mid-session drops whatever was recorded. **Every other Time Capsule argument is inert without `-timeCapsule 1`**, which enables it for a launch without writing the preference.

**The Time Capsule's rail lives on a REEL, and the reel is what a pause shows.** Pausing puts one modelled reel (`Models/Shell/TimeReel.usdz`, built by `Tools/timereel.py`) in front of the apparatus; a pinch draws the rail out of it and a second pinch winds it in. The rail is never on screen unasked — that was the owner's objection to the first build, and `TimeRailTests` holds the line. The reel also TURNS with the scrub, so the closed object is a readout, not a lid. Because the simulator cannot pinch, **`-scrubBack` draws the tape out as well as scrubbing**; to photograph the reel closed, pass `-pauseAfter` alone, since that is what a pause actually looks like.

**The Time Capsule (2026-08-07) is the one feature that spans all six modules.** Every model conforms to `TimeCapsuleRecording` (`Shell/TimeCapsuleSupport.swift`): it records an `Equatable` snapshot of itself into a `PhysicsCore.TimeCapsule` ring buffer at the end of every unpaused `step`, and the shell's one `TimeRail` (`Shell/TimeRail.swift`, mounted in `PlaygroundSpaceView` beside the palette) scrubs it while paused. Three rules govern additions:
- **Recording happens inside the model's `step`, in a function-scope `defer`** — never in a SpaceView, because models outlive the views and existing tests drive `step` directly.
- **The snapshot is the experiment, not the observer.** Dynamical state and entity sets in; display layers, bank flags and selections out. The stated exception is Electric Fields, where `capacitorOn`/`magneticFieldOn`/`chargesRespond` change the physics the recorded motion happened in.
- **Never snapshot an unbounded array.** Gravity Lab's orbit trails and Electric Fields' probe trail are rebuilt FROM the capsule on restore, under the same spacing rules the live code applies.
**Reading a snapshot's field list is not the check** — the same attention that writes the list is the one that forgets a field. `TimeCapsuleRoundTripTests`'s replay tests restore to mid-window, re-step with the identical dt sequence, and diverge measurably if any dynamical field is missing.

**When a toggle becomes a switch plate, check `reset()` restores the flag behind it.** **SIX** modules have had that defect — four found on 2026-07-31, and Gravity Lab's `keplerSweepOn` and Electric Fields' `chargesRespond` on 2026-08-03, behind lit plates, after this paragraph already existed. A flag with no visible control drifts out of `reset()` and stays wrong because nothing in the room contradicts it; the moment it gets a lamp, the lamp makes the claim every frame. **Reading `reset()` is no longer the check** — every previous fix was a test that LISTED the flags somebody had thought of, which is the same act of attention that missed them. `ResetCoverageTests` reflects over each model, finds every `Bool`, and asserts a mutated-then-reset model matches a fresh one. Add a flag and it is covered; you will be told to add a `flip` case rather than trusted to remember.
